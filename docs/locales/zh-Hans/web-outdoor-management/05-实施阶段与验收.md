# 实施阶段、验收与审阅事项

## 1. 本轮交付边界

设计已获用户认可，现已进入编码阶段。完整交付范围仍是浏览器全部配置维护、设备身份的 Geocaching 维护与去中心化 KML 轨迹共享。以下阶段和验收要求继续有效；阶段进展见 10，不能用某一基础模块通过测试替代完整交付。新增协议在实现对应操作前冻结注册表、错误表、wire schema、签名域和跨语言黄金向量。

## 2. 分阶段工作

| 阶段 | 输出 | 完成门槛 |
|---|---|---|
| P0 协议与覆盖盘点 | 全配置覆盖矩阵、板型 CDC/KISS/日志接入矩阵、协议注册表、测试向量 | 当前配置和协议事实核对完毕，预算和兼容策略确定 |
| P1 串口公共层 | 浏览器 transport、固件管理路由、会话权限、对象传输、任务查询 | 拆帧粘帧、背压、断线、重启恢复和旧客户端兼容 |
| P2 全配置维护 | schema、快照、事务、备份恢复、依赖控件 | 全部持久化设置覆盖，无未解释遗漏，保存/生效分离 |
| P3 Geocaching 作者工具 | 设备身份、草稿、更新/归档、目录回执和历史 | 原有 v1 互通，网页与设备交替维护，失败恢复 |
| P4 轨迹共享网络 | KML profile、manifest、目录/文件节点、Resource 分块、同步 | 多实现验签与文件校验，多节点检索/分发/归档 |
| P5 轨迹网页与设备整合 | Tracker 转换预览、上传发布、下载路线安装、历史 | 真机大文件及 LoRa/IP 预算验收、完整三功能体验 |

三个功能独立验收，共用 P1；轨迹协议可以在配置 UI 之外推进设计。首期不以身份私钥迁移、浏览器独立作者身份、实时位置直播、聊天社交或商业平台全部功能为依赖。

## 3. 模块落点建议

- `modules/core_hostlink`：纯 wire 编解码、协议注册、会话/分块状态机。
- 配置应用层：盘点实际配置 facade/TMS，再落 schema 与事务协调，不绕过现有保存入口。
- `modules/core_geocaching`：复用领域用例，抽离当前 UI 绑定的业务入口供串口调用。
- 建议新增 `modules/core_track_sharing`：manifest、版本、KML profile、传输与发布用例；platform 实现 SD/crypto/Reticulum ports。
- `site`：共用 serial client 和设备会话；配置、Geocaching、轨迹各自页面控制器。
- `tools`：轨迹目录/文件节点参考实现，与现有 Geocaching 服务区分命名空间。

上述落点为设计建议，必须根据依赖图确认，不能先复制大型 runtime 文件形成第二套逻辑。

## 4. 核心验收场景

### 串口

任意拆帧/粘帧、坏 CRC、未知版本、超长负载、重复与乱序块、断线、DTR 重启、端口占用、日志隔离、未经授权写入、旧客户端、能力缺失。每次任务恢复检查设备标识和作者指纹。

### 配置

矩阵逐项输入/边界/依赖/保存/读回/重启测试；不同协议和板型；字段秘密保留/替换/清空；并发修改；TMS/NVS 写失败和掉电；跨 schema 备份恢复。配置文件格式不被网页私自改写。

### Geocaching

设备身份发布新对象，端侧更新后网页更新，网页归档后端侧读回；错作者拒绝；重复请求幂等；版本分叉；目录确认丢失后恢复；USB 拔线后网络任务结果查询。

### KML 与 Reticulum

GPX/CSV/Binary 转 KML 保留真实数据；多段轨迹、缺时间/海拔、异常 XML、日期线；原文件与 manifest 篡改拒绝；最大预算文件流式传输；传输断点、掉电、磁盘满；两目录和两个文件来源；父链缺失/分叉；归档同步；第三方 KML 查看和设备路线安装。

不为文档阶段运行固件构建。实现阶段按仓库规定先对修改符号做 GitNexus impact，提交前 detect_changes，涉及配置/ESP 热路径运行栈检查，轨迹文件运行流式检查；长构建按后台日志/PID 规则等待终态。

## 5. 优先审阅的设计决定

1. 常规网页维护使用设备身份，私钥留设备；按用户后续明确的职责边界，设备通过 USB 证明身份及授权内容签名，浏览器通过电脑网络执行 Reticulum 发布、查询和归档。不得要求切换设备 RF 协议才能使用网页。
2. 串口沿用 HostLink 帧，并增加版本化管理信封及统一分块；RNode/KISS 与日志隔离在 P0 明确。
3. 全配置通过 schema 和覆盖矩阵完成，秘密及身份使用专用操作；保存与生效分别反馈。
4. Geocaching 保持现有 v1 网络格式；轨迹定义独立 manifest、发现和文件服务协议。
5. KML 是实际共享文件，签名 manifest 是作者、文件哈希和版本的证明；原始记录格式可保持。
6. 轨迹归档解释为发布 Archived 新版本；本地备份/移除是另外的操作。是否允许归档后重新激活需确认。
7. 多节点索引与文件保存，不承诺全网立即一致；冲突可见，保存回执不表示永久可用。
8. 8 MiB/100000 点/16 KiB 网络块为待压测预算，需按目标设备、LoRa 和 IP 网络测量后冻结。

## 6. 风险与待验证项

最高不确定性是目标板型的管理串口接入、全配置跨存储事务、当前 RNS 实现大 Resource/断点能力，以及轨迹多节点版本一致性。应先以小型跨语言协议原型和真机流式传输验证，再投入复杂页面。

目前文档是规划而非硬件可用性声明。上一轮 GitNexus 索引存在滞后，本轮代码依据以最新 main 的直接读取为准，图查询仅用于定位线索；实现前必须确认索引与当前分支一致。
