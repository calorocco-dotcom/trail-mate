## 身份 blob 不能按聊天记录处理

通用 blob 存储 API 的实际调用包含身份密钥，而不只是聊天数据：

- [MeshCoreIdentity](../../../../platform/esp/arduino_common/src/chat/infra/meshcore/meshcore_identity.cpp) 使用 mc_ident/priv64、pub32、ver。加载时从私钥重新推导公钥并检查一致性；ver 为私钥记录元数据，当前调用未提供 CRC 键。
- [EspPreferencesLocalIdentityStore](../../../../platform/esp/arduino_common/include/platform/esp/arduino_common/mesh/esp_preferences_mesh_identity_store.h) 默认使用 chat/pki_pub、pki_priv。Options 允许替换 namespace/key，默认值不能证明所有实例都使用相同存储位置。

Meshtastic 的当前两个使用方已核对：EspMeshtasticAdapterBridge 默认构造 local_store_，MtAdapter::initPkiKeys 默认构造临时 store，均未传入自定义 Options。当前源码的存储位置因此为 chat/pki_pub、pki_priv；后续新增调用仍需重新核对。

身份备份协议实际为 trailmate.identity.backup.v1，载荷含 Reticulum 组合公钥、对应私钥格式、identity hash、LXMF delivery 和身份代次；exportNativeIdentityBackup 导出 native 格式。它不包含上述 MeshCore/Meshtastic 密钥。网页的导出和恢复说明已用 11 种语言明确这个范围。

这两条发现仅证明存储归属，尚不证明网页已经能维护这些 RF 身份。各 RF 协议的身份是否纳入完整设备备份仍需解决，不能通过“当前协议未启用”跳过，也不能将普通配置表单等同于密钥备份。

### 通用 blob 接口实际调用核对（2026-10-12 后续）

已追踪 load/saveRawBlobFromPreferences 和 WithMetadata 的当前源码调用方：MeshCoreIdentity、LxmfIdentity 与 EspPreferencesLocalIdentityStore。后者实际类名为 LocalIdentityStore；MtAdapter::initPkiKeys 使用默认构造，当前没有找到另一个自定义 Options 实例。以下是存储结构证据，未读取设备秘密，也不扩张现有 Reticulum 备份范围。

| 调用方 | 实际存储 | 元数据与校验边界 |
|---|---|---|
| MeshCoreIdentity | mc_ident/priv64、pub32、ver | 私钥 64 字节，公钥 32 字节，保存版本 1；调用传入 crc_key=nullptr，没有独立 CRC。加载检查私钥长度并派生公钥，缺失/不匹配公钥会修复；加载并未根据读取的版本拒绝未知版本，不能把保存 ver=1 当成严格版本校验。 |
| LxmfIdentity | lxmf_ident/enc_pub、enc_priv、sig_pub、sig_priv，以及新的身份恢复记录 | 普通旧存储通过四项分别读取，验证签名密钥与 X25519 公私钥对应关系；身份恢复记录及代次使用专门校验路径。网页作者身份与备份使用此身份，不依赖当前 RF 协议。 |
| EspPreferencesLocalIdentityStore / MtAdapter | chat/pki_pub、pki_priv | 默认 Options，没有版本/CRC 键；检查长度与非零私钥。此接口自身不验证公私钥派生对应，不能用普通配置或 Reticulum 备份验收代替。 |

IDF 的通用 WithMetadata 实现支持可选 version_key/crc_key，不能据此推断所有调用都使用 CRC。MeshCore 当前是已找到的唯一 WithMetadata 上层调用方。普通配置 TMS 对 RF 身份私钥没有新增编辑或备份能力，这个范围缺口继续保留。

## Meshtastic 模块实际存储与规范化行为

直接核对 app_config_tms_ble_extension.cpp 和 meshtastic_ble_owner_hooks.cpp：两者使用 mt_mod/cfg 保存原生 meshtastic_LocalModuleConfig 结构体，加载检查结构体长度与其内部 version；这两个读写方没有另设 CRC 键。BLE 服务保存成功后请求同步 working TMS 配置。TMS 扩展将模块 protobuf 编码为 mt_module.format / size / chunk_count 和 3 个 chunk，恢复时严格检查格式、总长、分块长度、nanopb 解码和模块版本，再写回原存储。这个 namespace 不能通过此前 AppConfig 的 chat 标量段推算。

normalizeModuleConfig 调用共享 repairLegacyMqttConfig，实际包含以下保存后行为：MQTT 配置始终补齐；address、username、password、root 为空时使用设备默认值；缺失 map_report_settings 时补入默认地图上报配置。不能把网页移除这些本地参数解释成设备永久删除该配置，也不能把配置存在解释成功能启用。对应功能仍通过 MQTT enabled 或地图上报开关控制。

网页模块编辑器已为上述两类规则提供 11 语言的针对性说明，替换 MQTT/地图上报的通用移除提示，并在四个文本字段的 UTF-8 容量说明后标明留空会恢复默认值。未自动改写用户草稿，未公开默认密码或其他凭据值，其他模块保留原通用行为。
