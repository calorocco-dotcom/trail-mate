# KMZ压缩读取与主文件选择基础

2026-10-13。设备仍仅枚举COM67，60的手动RESET请求尚待用户完成；没有重新刷机。本批推进独立于设备的轨迹文件维护，完成浏览器压缩读取数据模块，尚未接入网页导入界面。

## 已实现的数据接口

新增readKmlArchive／chooseArchiveKml，使用现有fflate 0.8.3，不新增依赖。支持ZIP stored／Deflate、普通及预算内ZIP64目录与本地头、32／64位流式数据描述符、UTF-8／Unicode Path额外字段与旧CP437文件名。规范依据：[PKWARE ZIP APPNOTE](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT)。

全部中央目录、文件数量／大小、头信息一致性、数据范围与描述符先检查，再解压。拒绝绝对／上级／空路径段、反斜线／冒号／控制字符、精确重复路径、文件作为父目录、重叠／隐藏数据范围、加密、分卷、不支持的压缩方式和符号链接。不将文件名大小写或Unicode组合形式合并，避免有效资源被覆盖；目录项不混入文件资源。

输入65MiB、展开总量64MiB、单文件8MiB、65文件／256目录项、文件名4096 UTF-8字节。Deflate每次仅送1024压缩字节，实际输出不允许超过声明长度，最终逐文件校验长度与CRC32；定期让出事件循环并检查AbortSignal。返回前任何失败或取消都不返回部分文件集合。此预算属于浏览器，未给ESP增加代码、堆、任务或缓冲。

输出包含完整文件表与全部KML名称；根目录精确doc.kml优先，否则唯一根doc.kml大小写变体或唯一KML可自动选择。多份其它KML／多个非精确根变体需要明确选择。选择只复制原始KML字节，不重写XML或资源引用，也不赋予作者身份／签名证明。
