# 共享包原作者验证与路线提交

更新：2026-10-13。本批补齐共享包输入校验、公共缓存保留和最后路线提交的生产代码及原生验证。尚未接入管理串口安装/查询命令，也未接入离线资源解析/导航 UI；不能称浏览器完整包安装已交付。未整包 SDK 构建或刷写。

## 两个身份的边界

本地 USB 设备身份授权把文件写入这台设备；原始轨迹作者的签名证明轨迹内容。二者可以不同。

新增 SignedManifest 上传 kind 11，上限 4166 字节，两笔上传配额，设备生成目录 `/trailmate/web-signed`。原 unsigned Manifest kind 4 仍为 4096 字节；所有文件使用原 320 字节分块/双日志/封存机制。结构 reader 的独立模板上限扩到 4166，默认 4096 不变。

`SignedPackageFileCheck` 先核对当前本地演员绑定的封存上传实际字节，再验证原作者 Ed25519 签名、预期对象 ID 和版本 SHA。KML 的大小/摘要须匹配该签名；v2 再核对索引/资源及实际 KML 几何。v1 不能夹带附件映射，v2 assets=nil 也不能夹带无绑定附件。

`TrackPackageInputOwner` 冻结本地作者摘要、代次、媒体、上传 ID、预期对象/版本，使用短期 PSRAM。错误签名、错误版本、其他演员的上传、代次变化、换卡或取消不会产生 Ready。这里不调用本地内容签名，也不把原作者替换为设备作者。

输入 Ready 仅证明输入包已核验；不是当前网络版本、网络目录接受、安装或导航的证明。

## 公共缓存与自己的发布历史

公共安装包保存于 `/trailmate/packages/<完整版本SHA>/`：

- `manifest.cmp`：原始签名容器，逐字节保留。
- `route.kml`：原始 KML。
- `index.cmp`：原始附件索引（如存在）。
- `<资源SHA>.ast`：资源字节。

临时文件各有独立后缀。所有路径由设备从版本/资源 SHA 生成，URL、引用、作者文件名及资源 ID 不直接成为文件路径。

`TrackPublicPackageRetention` 使用不可变复制/摘要核验和前缀恢复，先保留签名与 KML，再分块保留索引及提供资源。不建立整份索引/资源正文缓存，不写自己的 ObjectHead/Reservation，不把他人轨迹登记为自己的作品。既有自己的发布目录 `/trailmate/tracks` 保持独立。

公共缓存根最多 64 个直接条目，未知/孤儿条目也计数；每份版本缓存最多 134 个条目、64 MiB 加 64 KiB 元数据余量。子目录、未知文件及过量字节不能被跳过。根枚举和文件枚举工作区均使用 PSRAM，申请失败返回 Busy。

已有最终文件重新核对实际大小和 SHA256；临时文件只有前缀与源一致才续接。损坏的目标/前缀不自动删除或覆盖。

## 最后提交可见路线

`InstalledPackageBinding` 是固定 154 字节的 TMPK/v1 本地记录，包含完整对象/版本、KML/索引摘要及大小、条目数和 64 位可用性。CRC16 检测损坏/部分写入，不能认证原作者。后续读取必须验证公共缓存中的原始签名及对象/版本/索引/实际文件。

`PackageRoutePublication` 和 ESP `TrackPackageRoutePublication` 在公共缓存 Ready 后才创建。路线命名 `/routes/p-<完整版本SHA>.kml`，绑定记录 `.rpk`，临时文件 `.ktm/.rpt`；容量为 80 字节的设备路径槽，旧路线安装的 77 字节路径槽不变。

顺序为：完整公共缓存核验 → 保存/同步并读回绑定记录 → 复制并核对 KML → 发布最终 `.kml`。因此绑定记录存在不代表路线可见，最终 `.kml` 出现才是路线列表的可见步骤。

绑定记录部分写入按预期字节前缀恢复；已有记录必须完全匹配，损坏/冲突不覆盖。rename 即使返回失败，也用实际目标读回决定是否已经完成。之后相同安装再次执行会验证现有文件，不重新签名或替换别的路线。

身份、媒体和调用者提供的存储/活动路线策略在步骤中继续检查。策略 Busy 不推进事务；取消/错误后保留可恢复的命名文件，不做整个目录回滚。最终磁盘操作后的异常不能被解读为“肯定没有安装”，仍需新的查询/读回入口确认。

路线目录预算为 32 MiB 加 64 KiB 元数据余量、最多 256 个条目，包含未知/孤儿文件。按当前版本的实际最终/临时文件预留剩余字节及条目；重复读取已完成安装不会重新预留已有文件的全部空间。

## 内存与验证

输入 owner <=18432 字节，公共保留 owner <=768 字节，路线提交 owner <=1280 字节，附件工作区沿用 <=9216/<=7168 字节限制；SD Impl 另计。这些是原生编译通过的短期 PSRAM 结构约束，不是实机运行内存测量。未加入管理串口新全局槽/常驻目录表，也没有扩大串口 frame/arena。

实际生产校验、SD adapter、签名验证、不可变复制、公共保留和提交类在原生测试中编译，底层 SD/堆模拟，使用实际 SHA256/Ed25519。覆盖：

- 不同本地/远端作者的 v1/v2 验签，原始签名字节保持，本地签名计数为 0。
- 错误签名/预期版本/上传演员，代次变化、换卡、取消和冻结输入不被外部修改。
- 公共复制写入失败后保留前缀，再创建复制作业恢复；完成后重复执行文件不变。
- 公共缓存未 Ready 时拒绝创建路线提交；策略 Busy 没有副作用。
- 绑定记录写入失败/恢复、记录单独存在时无 `.kml`、完成后重复安装。
- 逐字节损坏 CRC 记录均拒绝，损坏的已有记录不覆盖。
- 根缓存/路线目录未知条目配额、短 scratch 拒绝，不写自己的发布头目录。

模拟目录读取曾错误返回递归文件名，已修正为真实接口的直接子项/目录语义后，既有原生回归仍通过。6 项相关 CTest、16 项 Node（包括既有实际 CMP→C++ 包签名互操作）、ESP 栈/流式读取及差异检查通过。

图片 fixture 仅验证字节保存，不能证明 PNG/JPEG 解码；并未验证真实 USB、SD、LVGL、导航或掉电。本批未 SDK 构建/刷写，最新编译镜像仍 bdb92171…（51 操作、静态 RAM 95572），实际已刷仍 b733480e…。

## 继续接入的完整范围

仍需把这些作业接入现有单 scheduler slot、串口安装/持久查询、活动路线及清理策略，并在所有入口真实可用后公告能力；当前未公告新安装操作。需要实现从 `.rpk`/原始签名/索引验证后解析离线附件，避免 CRC/exists 被误当作作者证明；导航与预览才能实际使用资源。

网页仍需多语言附件维护、完整包下载/导出、安装交互和跨刷新检查点。GPS 几何/高度/时间语义、实机与掉电、公网验收保持原范围。这里的底层文件提交不替代以上交付。
