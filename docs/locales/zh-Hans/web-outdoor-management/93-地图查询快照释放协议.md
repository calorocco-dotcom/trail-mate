# 地图查询快照释放协议

2026-10-14，接92。上一批回收已读完的冻结集合；本批处理正常在线浏览时只读第一页、移动地图和自动刷新造成的旧查询占用。新增可选网络协议与浏览器生命周期管理，不修改设备固件／串口命令，不构建SDK、不刷入，不增加设备RAM。

## 协议与所有权

Geocaching网络协议仍为 `trailmate.geocache`，CMP1版本仍为1。能力操作0的空请求体保持原响应，包括既有发布证明能力；新浏览器另发 `[2]` 查询可选扩展能力。旧服务返回已认证 `400 malformed_request` 时继续按原能力工作，不发送释放请求。新服务的扩展能力声明操作6，其他能力参数与原响应保持一致，浏览器拒绝不一致或重复／非法操作列表。

| 网络请求 | 含义 |
| --- | --- |
| 操作0，`[]` | 原能力响应保持 |
| 操作0，`[2]` | 扩展能力；操作6代表浏览查询释放 |
| 操作6，`[snapshot_id]` | 释放同一已认证传输来源创建的操作2快照 |

响应 `[snapshot_id, released]` 的released为整数0或1：1表示实际删除冻结集合，0表示已无集合。不是USB命令6，也不是轨迹协议的上传操作6。轨迹查询使用自己的无持久分页集合设计，未接入此Geocaching操作。

所有权按Reticulum/LXMF已验证的传输来源绑定，不能释放另一来源的快照，不能释放目录复制分页／检查点，也不删除内容、版本链、发布证明或日志。操作和回复在SQLite事务中提交；回复丢失后使用相同请求ID取得原结果，不能换ID造成重复动作。服务重启后仍可核验原回复。

显式释放写入来源绑定的query_releases记录，保留到请求重放窗口结束。已释放查询的原请求重放返回410 query_released，旧续页不能继续；不是继续发出带失效续页的旧200缓存。当前未被释放的查询仍保持原七天承诺，上一批完整分页读完后的原页重放保持。

## 浏览器行为

新视野、筛选或自动刷新替换查询前，先释放已经丢弃的旧续页，再申请新快照。“加载更多”保留当前续页，不触发释放；最后一页读完直接移除本地登记，服务按92回收。

若旧查询在请求过程中被新视野取代，仍核对其已认证回复结构，并登记合法快照，随后由新查询释放，避免仅因界面代次变化把服务资源遗失。已经被排队后续查询取代的任务直接跳过，不重复建快照。

释放错误／回复丢失／回复不匹配时保留原登记与固定请求ID，停止新快照申请并允许后续重试。目录对象或epoch改变、来源不再ready时不猜测原服务目标；旧服务只能按原到期机制处理。关闭客户端清本地登记与重连，未承诺页面卸载时能取得服务端释放确认。

正常查询只登记有续页且能力已明确支持的快照，通常最多三个来源乘两个日期线范围。旧服务没有此登记／释放请求；数据库新表与索引仍兼容schema version 1，不改设备原能力解析器或固件驻留缓冲。
