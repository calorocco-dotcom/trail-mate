# PNG解码与图片缓存内存约束

更新：2026-10-13。延续33的离线附件接入，本批补齐Wio L2路线图片缓存的PNG解码，并保留完整包安装/查询与原作者证明。

## 实现边界

设备根据文件内容识别PNG，不依赖 `.jpg` 缓存后缀。PNG进入与JPEG相同的BMP缩略图/查看图发布事务：先完整检查PNG结构、CRC、块次序与EOF，再流式解码到既有200×120或320×180目标；完成后才写临时BMP、同步并重命名。错误、截断、换卡、申请失败、写入/同步/重命名失败均不能提交新的可见BMP。

支持灰度、调色板、RGB、灰度带透明度、RGBA，各自合法的1/2/4/8/16位深，五种过滤器、Adam7隔行与tRNS透明色。16位透明匹配使用完整样本精度，显示颜色转换为8位。透明部分合成白底，采用保持比例的居中裁剪；整数最近邻采样避免放大/裁剪边界浮点误差。PNG颜色管理/动画不由该缓存解释。

资源保存/签名上限保持8MiB。设备图片呈现额外限制：每边不超过8192、总像素不超过3200万、块数不超过65536、目标不超过320×180。不把尺寸超限文件截成成功，也不申请完整源图像。CRC/Adler只证明格式与损坏检查，不能替代原作者签名和资源SHA；原包核验仍由100/101及既有存储证明完成。

## 分配与依赖

路线缓存使用独立的pngle与inflater实例，原LovyanGFX接口不改。解码上下文、最多65552B扫描行和 <=768B 的CRC/传输/裁剪工作区均短期PSRAM，申请失败不退回内部堆；解码结束释放。原生测试中的caps计数也确认没有内部申请。

共用inflater关闭了Adler核对，并在环形字典模式下缺少对“已经生成多少历史”的检查。本实例补回Adler、严格结束、无进展拒绝和回溯距离核对，且初始化字典；不能从未生成的字典位置取数据。还修正小尺寸Adam7末尾、过滤器前缀/跨pass清理、调色板越界和16位透明样本处理。来源与本地差异见 `third_party/route_png/README.md`，许可保留。

BMP行缓冲和输入/输出SD backing也优先PSRAM。现有图片缓冲在设备有PSRAM而外部分配失败时停止，不再挤占内部堆。没有PSRAM时PNG不启用；原JPEG保留无PSRAM设备的既有内部预算规则。包校验大工作区仍在复制/解码前释放，没有新增常驻队列、目录表或线程。

JPEG回归发现P4的实际LVGL tiny JPEG输出BGR，而ESP ROM输出RGB；缓存转换按后端处理。Wio L2的原ROM通道转换保持，原生测试通过实际P4 tiny JPEG验证红色BMP，未伪装成Wio ROM实机证据。

## 当前验证

7项相关CTest、9项Node实际协议回归、ESP栈/流式读取/差异检查通过。PNG测试逐像素比较生产缓存函数写出的BMP，覆盖所有合法色型/位深、tRNS、隔行、全部过滤器、原尺寸/裁剪/放大、字典回绕、最大扫描行、真实压缩PNG及真实JPEG。

异常测试覆盖CRC/Adler错误、非法历史回溯、额外/不足栅格或流字节、非法过滤器/调色板、重复IHDR/未知关键块/IDAT次序错误、尾随字节、文件/尺寸/块数上限、每个申请点失败、无PSRAM、换卡及写入/同步/重命名失败。使用真实生产代码/解码器/压缩流，SD/堆与平台环境模拟；这些不是实际屏幕、触摸、SD掉电或运行峰值测量。
