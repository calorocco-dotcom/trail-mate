# RF 身份单记录存储与启动保护

2026-10-13。本批为 MeshCore／Meshtastic 密钥维护补齐存储与启动前提，已经修改实际身份类和存储类。没有新增网页按钮或 USB 能力公告，不能据此宣布 RF 身份导出／恢复功能完成；现有 Reticulum 备份范围保持原样。

## 为什么先修改存储

原 MeshCore 的 priv64/pub32 和 Meshtastic 的 pki_priv/pki_pub 分别写入；部分失败可能留下不同步的公私钥。MeshCore 初始化原先在 loadFromPrefs 失败后生成新密钥，Meshtastic PKI 初始化也把损坏／存储读失败当成不存在。这样的路径不适合接入浏览器恢复：一次存储错误不能默默换掉身份。

实际修改：

- 新增共用 radio_identity_record.h，MeshCore 与默认 Meshtastic 身份各在自己的原 namespace 使用 native_rf1。单记录同时保存格式、协议种类、RF 本地代次、公钥、原生私钥与 CRC；112 字节固定长度。MeshCore 私钥为 expanded Ed25519 64 字节，Meshtastic 为已夹紧的 X25519 scalar 32 字节，未用位置必须为零。
- 单键提交明确区分 Committed、Indeterminate、TargetChanged、Invalid 与存储错误。提交报错不推断回滚；启动重新读取并验证完整记录。CRC 只用于损坏检测，读取后的实际公私钥对应校验不可省略。RF 本地代次独立于 Reticulum 作者身份代次，不改变网页账号。
- Meshtastic clear 写入带代次的持久空记录，不在删除新记录后回读旧分键。旧私钥仍保留在旧键中，但升级固件不再激活它；重新生成或导入的新记录接续 RF 本地代次。
- 未存在新记录时继续兼容旧键。默认 RF 旧键直接读入调用方工作区，不经 vector 复制；私钥缺失／类型错误／长度错误／不支持的 MeshCore ver 不生成新身份。MeshCore 的有效旧私钥仍可派生并修复缺失／不匹配的旧公钥，修复结果保存为新单记录，失败不启用。
- Meshtastic 加载及保存验证已夹紧标量与实际派生公钥对应；坏公钥不能只凭非零私钥被接受。默认 Options 使用新记录，显式自定义 namespace/key 的 Options 保留原独立键路径，避免不同 key pair 争用同一 native_rf1。当前已核对的两个生产调用方均使用默认 Options。
- MeshCore 导入先提交，再替换运行中的公私钥；提交不确定时清空运行态密钥并停用，重启读取实际记录。Meshtastic PKI 初始化只在 StoreFailure::NotFound 时生成，Corrupt／IoError 时停止并清空运行态密钥；新身份保存失败也不置为 ready。

新记录具有单键提交边界及校验规则，但本轮只有模拟 NVS 故障证据，没有 ESP NVS 实际掉电证据。不能承诺所有故障都会保留旧键；完整旧值／新值／拒绝损坏与不存在是不同结果。恢复损坏记录的显式修复授权、并发身份操作互斥及 USB 重启确认仍须接入后续维护流程。

## 内存与兼容性

RadioIdentityWork 只保存一个指针；每次按需申请 144 字节工作区，完成或失败均通过 volatile 清零并释放。在运行时存在可用 PSRAM 时只尝试 PSRAM，申请失败不回落内部堆；无可用 PSRAM 的板型允许有界 144 字节内部申请。Wio L2 已确认有 8 MiB PSRAM，仍须以最终镜像／实机运行验证实际路径。

没有给 MeshCoreIdentity 或 Meshtastic 存储对象增加常驻字段，没有新增线程／队列或完整身份缓存。MeshCore 旧公钥修复期间的读取与提交可能同时持有两份 144 字节短期工作区；不能把单份尺寸当成全流程峰值。默认旧键读取去掉原 vector 暂存，有助于避免内部堆上的短期秘密副本，未量化为运行堆节省。

旧键没有覆盖／删除。老固件不识别 native_rf1，降级时可能再次加载旧 RF 身份，因此跨固件降级不能作为本批已支持的身份迁移。Reticulum 的 native_v1／epoch、网页作者、现有内容版本链和配置 TMS 格式没有改动。

## 已执行验证

1. radio_identity_record 原生目标覆盖两种记录长度、代次比较、提交不确定后的重新读取、持久空记录、旧键保留、CRC／零填充／错误类型／旧版本和存储不可读，检查打开的 NVS 句柄全部关闭。这里的密码学 callback 为模拟，不能单独证明密钥真实性。
2. radio_identity_storage 直接编译实际 MeshCoreIdentity、EspPreferencesLocalIdentityStore 和生产 MeshCore 密码学源码，链接实际 Ed25519／Curve25519。验证导入、重新构造读取、坏 CRC、CRC 正常但密钥不匹配、提交不确定后重启读取、旧私钥缺公钥修复、部分旧键拒绝、真实公私钥匹配和非默认 Options 隔离。
3. 实际 MtAdapter::initPkiKeys 由 CMake 提取，配套字段与日志辅助函数模拟；它调用实际存储类和密码学库。正常读取、损坏记录、内存不足、存储读错误及恢复可读后再次初始化通过。新身份 RNG 路径在此专项中刻意中止，证明损坏／读失败不会进入生成。MeshCore 新身份初始化的熵源使用明确标注的确定性测试源，不能证明硬件随机质量。
4. ESP 工作区分配器模拟记录能力、次数和释放：PSRAM 分配失败只尝试一次、不转用内部堆；无 PSRAM 的有界路径可用；释放前全部工作区字节为零，分配与释放平衡。
5. 与原 Reticulum 实际原生密钥验证、身份记录、Wi-Fi 保存及配置应用一起，8 项相关 CTest 通过；7 项 NVS／Preferences Node 测试及 ESP 栈检查通过。NVS 清单同步为 1606 文件、98 候选调用、8 来源、18 别名；新增调用属于 RF 单记录，不是新增配置表单数量。
6. CI 加入只安装 Crypto 0.4.0 源码的步骤，不构建固件；CMake 的必需 RF 测试开关使缺少依赖时明确失败，避免条件跳过被当成通过。本地用 PlatformIO 6.1.19 验证安装命令和目录布局，Curve25519 源码摘要与现有构建依赖一致；尚无远程 CI 结果。
