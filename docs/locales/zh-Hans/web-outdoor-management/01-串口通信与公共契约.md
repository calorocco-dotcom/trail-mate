## 1. 目标与分层

三项功能共用一个 USB 管理会话。分为 USB CDC 字节流、HostLink 帧、管理请求、持久化业务任务四层。浏览器不直接修改 NVS、TMS 或任意 SD 路径。

已有依据：`modules/core_hostlink/hostlink_protocol.md`、`platform/esp/arduino_common/src/hostlink/hostlink_service.cpp`、`platform/esp/arduino_common/src/usb/usb_cdc_transport.cpp`。不同板型及 IDF/Arduino 接入需独立验证；RNode 数据交换入口当前可切换到 KISS，管理通道必须明确与 KISS 的互斥或独立端点策略。

## 2. 帧与兼容

保留现有 `HL | ver | type | seq16 | len16 | payload | CRC16` 及 512 字节 payload 上限。先用现有 HELLO/HELLO_ACK 完成握手，再协商新增管理能力。旧客户端及旧命令行为保持兼容。

建议保留扩展帧类型 `0x20 MANAGEMENT_REQUEST`、`0x21 MANAGEMENT_RESPONSE`、`0x87 MANAGEMENT_EVENT`；实施前对完整类型表检查碰撞。扩展负载使用有界 MessagePack，禁止把内存结构体直接 memcpy 成 wire 数据。

请求信封：`[schema=1, session_id:bin16, request_id:bin16, operation:u16, body]`。

响应信封：`[schema=1, session_id, request_id, status:u16, body]`。

事件信封：`[schema=1, session_id, event_seq:u32, topic:u16, body]`。

HostLink seq 仅关联帧；request_id 关联请求重试；operation_id 关联持久化副作用。三者不得混用。消息精确字段数、字节长度及整型范围均须校验，不接收尾随数据。

## 3. 会话与访问控制

流程：点击连接 → 浏览器选端口 → 打开 CDC/DTR → HELLO → 管理协商 → 读取能力 → 设备确认维护会话 → 读取快照。

会话状态：Disconnected / Negotiating / ReadOnly / Maintenance / Closing。GET_CAPABILITIES 返回设备型号、固件版本、设备稳定标识、启动标识、schema 版本、可用服务、分块和任务预算。身份指纹在 UI 中可核对。

浏览器串口授权只说明用户允许页面访问端口，不能证明固件请求来源可信。设备侧维护授权限定会话和超时；配置写入、内容发布和身份恢复使用分开的权限。CRC 只用于传输错误检测，不是授权。设备若无显示屏，维护授权使用明确的物理按键/维护模式流程，不能默默跳过。

USB 日志与协议帧必须独立端点或统一封装，禁止未封装 Serial 输出污染业务字节流。串口被监视器占用、DTR 导致重启、拔线和休眠均有专门状态提示。

## 5. 分块与流控

大 schema、配置快照、记录和文件统一走对象传输。TRANSFER_BEGIN 绑定对象类型、长度、SHA-256、方向和来源快照，返回 transfer_id、chunk_bytes、有效期。分块大小根据 512 字节帧扣除完整信封开销计算，初始目标 384 字节，必须用编码向量证明可装入。

CHUNK 包含 transfer_id、offset:u32 和 bytes；默认一个未确认块，设备确认后发送下一块。设备采用固定深度缓冲与背压，不在 ESP 栈上放置整份配置或文件。重复相同 offset/data 返回原确认；同 offset 不同数据中止传输。FINISH 在总长度与完整哈希校验通过后才生成可引用的对象句柄。

上传落到临时对象，完成验证后原子安装；下载绑定不可变快照。拒绝任意路径、目录穿越和覆盖活动录制文件。恢复查询返回已持久化的连续偏移；恢复后从此偏移继续，最终仍校验完整哈希。掉电可能丢失未同步块，不能按已接收的 RAM 偏移恢复。

## 6. 长任务与幂等

COMMIT 返回 operation_id/job_id 与受理状态，不等于完成。状态为 Accepted / Preparing / Persisted / Transmitting / AwaitingReceipt / Confirmed / Conflict / Failed / CancelRequested / Cancelled。

具有副作用的 operation_id 连同输入摘要和结果持久化。相同 ID、相同输入返回原任务；相同 ID、不同输入返回 CONFLICT。幂等记录保留时间与任务存储预算由能力返回；过期任务 ID 返回 EXPIRED，不自动执行成新操作。

拔线不取消已持久化任务。重连核对设备和作者身份，再 JOB_GET。事件可丢失，状态查询是恢复事实来源；事件序号有缺口时重新读取快照。取消只阻止尚未完成的本地阶段，不能撤回已向网络发送的发布。

## 7. 身份使用

AUTHOR_INFO 返回 combined_public_key:bin64、identity_hash:bin16、相关 destination、identity_generation。AUTHOR_PROVE 签署带协议域、会话、随机挑战的固定格式证明；它不是任意签名接口。

业务 PREPARE 返回规范内容摘要、作者及版本；COMMIT 绑定这些值。设备签署通过校验的 Geocaching/轨迹对象。常规会话不导出私钥。身份更换使旧 prepare token 失效；任务保留原作者信息，禁止用新身份重新签署旧作者更新。

身份备份/恢复另设设备确认和加密文件流程，验证公钥、身份哈希、目的地址及签名兼容性。普通配置导出必须标注是否包含秘密，身份不作为一个隐藏配置字段出现。

### 作者证明的具体 wire（已接入固件与浏览器，待真机验收）

- AUTHOR_INFO（1）：请求 `[]`；响应 `[public_key:bin64, identity_hash:bin16, lxmf_delivery_destination:bin16, identity_generation:uint32]`，代次范围 1..4294967295。
- AUTHOR_PROVE（2）：请求 `[challenge:bin32, expected_generation:uint32]`；响应为 AUTHOR_INFO 的四项再追加 `signature:bin64`。身份代次不匹配应返回 STALE_IDENTITY。
- 签名字节为 UTF-8 `trailmate.hostlink.author/v1\0`（包含末尾一个 NUL）与 canonical CMP1 `[1, session_id:bin16, challenge:bin32, public_key:bin64, identity_generation:uint32]` 拼接。固定业务域，不提供任意签名字节接口。
- 浏览器先验证 `SHA256(public_key)[:16] == identity_hash`，再验证 LXMF delivery 地址：`SHA256(SHA256("lxmf.delivery")[:10] || identity_hash)[:16]`。证明响应必须保持同一公钥与代次，签名还须绑定当前会话及新挑战。
- AUTHOR_INFO 自身不是持有私钥的证明。只有验签通过才建立浏览器作者状态；断线立即清除该状态。代次应在设备身份替换/恢复时更新，不能把 USB 型号、MAC、网页身份或静态常量作为身份代次实现。

管理能力现已声明操作 1/2，经 MeshAdapterRouter 的锁保护路径使用现有 LXMF 身份签名。代次记录为 NVS 单个 20 字节 blob（计数与公开身份哈希），正常启动保持代次，密钥变化递增；显式身份恢复需调用强制递增入口，损坏记录/计数耗尽/写入失败不发布有效代次。身份对象仍为 200 字节，证明/响应复用命令 payload。

C 固件编码与 Ed25519 库生成的证明已通过浏览器验证；错误会话、挑战、公钥与代次的正反例已覆盖。已有但不完整/损坏/不可读的身份拒绝自动生成替代密钥；签名公钥不匹配拒绝自动改写。真实 USB、身份恢复交互及业务 prepare token 失效仍须验收。

### 轨迹临时传输维护 wire（2026-10-12）

- 候选与一份日志删除后失败，后续调用仍可凭剩余日志继续清理；成功后相同请求返回成功且不创建新上传。两份日志均不存在时，候选也不存在才视为幂等完成；存在无日志候选的孤立文件时拒绝清理。损坏、身份不匹配、未知 I/O 不当作“文件不存在”。清理范围只包含上述传输的候选与 A/B 日志，不触及正式签名清单、版本头、保留 KML 或发布收据。
