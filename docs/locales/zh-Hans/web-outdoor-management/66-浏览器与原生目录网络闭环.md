# 浏览器与原生目录网络闭环

日期：2026-10-13。分支：`feature/web-device-outdoor-management`。本记录覆盖真实本机 RNS/LXMF 传输；不代表公网部署、USB 作者与网页完整页面、全部配置交互或三个功能已整体交付。

## 测试路径

Edge 中实际 `TrackDirectoryClient` → 浏览器 RNS/LXMF → 原始 WebSocket 数据包桥 → TCP/HDLC → 两个独立 Python Reticulum 目录进程。目录运行生产 `TrackDirectoryService`、`TrackApplication`、BlobStore、DirectoryIndex 和 RegionCatalog。桥只转发原始 Reticulum 包，不解析业务、持有作者身份或替代签名验证。

作者为合成独立身份；测试明确要求它与浏览器网络传输身份不同。签名、消息传输、目录回执验证与文件持久化真实执行。未连接 USB 或 RF，未使用设备私钥或公网目录。测试通过构建的浏览器协议入口调用生产客户端，不是轨迹整页交互验收。

## 通过的流程

1. 从签名发现信息核验两个目录身份、代次及能力，包含附件和元数据查询扩展。
2. 分块上传 2,950 字节原始 KML、104 字节附件索引和 67 字节 PNG；校验内容摘要及附件完整性，签署并发布第一版。
3. 使用同一发布请求 ID 重试，验证回执与版本一致。
4. 使用地图视窗及活动／标签过滤查询；切换到另一视窗后为空。
5. 实际网络逐级读取合成国家→省→市→区四级目录，逐级校验边界摘要、读取对应轨迹；末级无子区。
6. 通过稳定轨迹 ID 读取完整签名包，确认原始 KML 和 PNG 字节一致。
7. 发布第二版，再发布第三版归档；活动查询不再返回归档对象，归档查询显示第三版。
8. 正常停止并重新启动两个目录；保持各自身份和 epoch。使用全新浏览器传输身份，按 ID／版本读取第三版归档及第一版历史，原清单、签名、KML 和 PNG 保持一致。

两目录由作者分别发布，不以此声称轨迹目录之间已经自动复制。

## 4 秒延迟的原因与修正

上次 300 秒测试期限中断了仍在推进的完整流程。新增浏览器逐请求和目录处理观测后，上传／附件查询／发布均实际成功；目录业务处理通常只需几十毫秒，但多数网络往返为约 4 秒。

已安装的 LXMF 1.1.1 在 `process_outbound` 遍历待发队列时删除已完成项，会跳过紧随其后的新回复；默认周期处理间隔为 4 秒。新测试直接调用该已安装库的方法，复现“旧项移除、新项未发”；再次推进原处理器后发送。测试替身仅提供消息／链路状态和无实例的路径持久化依赖，不替代库的队列处理。

Geocaching 和轨迹目录现在在既有服务线程中，仅在存在未完成回复时每 100 毫秒至多推进一次原生处理器。继续使用 LXMF 原锁、重试、交付证明、印花与队列上限，不改库的全局周期，不增加线程，不增加设备 RAM。这里只调整电脑侧服务。

同一轮诊断中，修正前 94 请求中位 3,998 毫秒／P95 4,001 毫秒；重启采用修正后 28 请求中位 119 毫秒／P95 135 毫秒。随后从头完整复测，再扩展为四级行政区测试：最终 148 请求中位 **120 毫秒**、P95 **168 毫秒**，流程到重启核验约 **24.1 秒**。这是本机测试数据，不能外推公网、8 MiB 文件、RF 或硬件吞吐。

## 其他验证与交付边界

- 新原生回复队列复现、频率限制、闲置不处理和原锁保护测试通过。
- 10 项相关 Python 业务／附件／版本／区域／队列回归通过；另 Geocaching 身份延迟准入及持久签名证明 3 项通过。
- 原生轨迹跨进程发布与新读取者重启回归通过，退出 0。
- Geocaching 原生跨进程发布、同请求确认、查询、第二版更新及第一版历史验证通过。旧网络脚本仍要求能力仅 0–4，与新增签名证明命令 5 不符；修正为 0–5。保留已发布合成状态直接恢复重启读取，核验原目录身份／epoch、第二版当前、第一版历史和同步基线／空增量，退出 0。恢复模式复用原 TCP 端口及配置，不重写原 RNS 配置。
- Geocaching 自动复制另复现生产 `ReplicaScheduler` 同样写死 0–4，导致包含命令 5 的目录被隔离。现在核验基础命令完整、整数／范围／去重／有界数量，并接受合法扩展；保留版本、消息预算、游标与其他能力约束。6 项复制回归通过，覆盖传统目录、新证明能力、未知合法扩展及坏列表。真实两个原生目录之间自动复制原始签名对象后关闭源目录、重启副本；新读取者在源离线时仍取得准确第二版签名原文，退出 0。复测复用已有合成状态，仅将测试副本的旧失败调度设为立即重试；未删文件或重置真实服务。
- 轨迹真实浏览器网络、队列回归和 Geocaching 原生发布／自动复制／离线恢复已加入 CI；增加既有原始桥的固定版本 WebSocket 依赖。加入不等于远端 CI 已运行。
- 本批无固件构建／刷机／设备配置写入。最新 Wio L2 7c 固件和用户验收的约 87K／297K 内存表现保持。
