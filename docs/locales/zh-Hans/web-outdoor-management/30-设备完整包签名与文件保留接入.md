# 设备完整包签名与文件保留接入

更新：2026-10-13。本批将 [29](29-设备附件分块校验与上传存储.md) 的附件校验作业接入实际准备、签名及文件保留状态机，并完成浏览器 API/实际 C++ 状态机的本地互操作。仍不是完整附件 UI、导航安装、公网或实机验收。

## USB 协议与旧设备兼容

新操作 `TrackPackageSignPrepare = 99` 使用：

```text
[operation_id:bin16,kml_upload_id:bin16,manifest_upload_id:bin16,
 author_generation:u32,parent_revision_hash:bin32|nil,
 attachment_bindings_upload_id:bin16|nil]
```

普通进度与操作 96 相同，返回 `[operation_id,ready:u8,object_id|nil,revision_hash|nil,revision,signature64|nil]`。只有所有阶段完成才 ready=1 并返回签名。未完成进度中的对象/版本摘要/签名都是 nil，revision 为 0。

原操作 82/96 继续只接受原五字段请求，不接受六字段或 v2 清单。99 只接受六字段及 v2 清单。v2 assets=nil 时最后一个字段必须 nil，且不能附带无绑定资源；有索引时最后一个字段必须是正确的封存映射上传。

新增上传 kind 10（1100 字节上限、两笔上传配额）保存附件映射：

```text
[1,index_upload_id:bin16,packed_resource_upload_ids:bin(count*16)]
```

映射按索引的原始顺序排列，零 ID 明确省略资源。映射不进入作者签名；其每项必须满足已绑定索引的 SHA256/大小，且所有实际上传均绑定当前设备作者和代次。文件本身从双日志核对后再实际重读 SHA256，不靠日志 CRC 信任正文。

映射作为最后一份上传，准备请求明确引用它。单个 HostLink 帧仍为 512 字节，传输块仍最多 320 字节；64 项 ID 不进入一个管理请求，不扩充命令 arena。kind 10 的路径由设备生成在 `/trailmate/web-package`，不接受用户路径。

USB 自动启动目标的能力列表新增 99（51 项）。浏览器 v2 维护必须看到明确的 99，不能从旧 Transfer/96 推断支持；v1 继续沿用原逻辑。网络目录操作 14 的 opt-in 协商不变，也不依赖设备 RF 模式。

## 准备与签名顺序

1. 同一次当前身份读取确定公钥、摘要及代次，冻结请求与媒体，持有现有存储排他租约。
2. 核对 KML/清单的封存上传记录，重读并验证清单实际字节；校对作者与 KML 绑定。
3. v2 读取并核对封存映射；解析受 SHA256 绑定的索引，逐项核对上传元数据和资源实际摘要。必需缺失拒绝，可选明确缺省允许部分可用。
4. 从实际 KML 字节核对长度、SHA256、几何范围和点数。原 KML-only 入口仍拒绝 v2；只有实际包证明匹配当前索引/KML 的新入口允许继续。
5. 沿现有当前头/父版本/Checked 预留规则签名，持久保存签名清单和 Signed 记录，再验证保存的签名。ESP 公钥验签适配器已明确支持 v1/v2 两个域，仍拒绝其他版本/错误终止符。
6. 保留 KML、索引及所有提供资源，逐文件核验实际目标/临时文件与摘要。全部完成后才返回准备成功及签名。

逐步重读当前身份/代次及媒体；改变后不继续旧工作。新作业仍使用现有单 scheduler slot，不增加常驻队列/协议缓冲。

签名可以在复制完成前已持久保存到 SD，但此时 USB 不返回成功或签名；后续使用相同操作/内容绑定重试，核对已有签名并完成复制，不再签一次。Signed 也不是网络已接受/Committed 的证明。

## 文件保留与恢复

KML 沿用对象下原 `.kml/.ktm`。索引使用 SHA256 派生的 `.idx/.itm`，资源使用 `.ast/.atm`。URL、相对引用、图片名称和资源 ID 不成为 SD 路径。不同条目可复用相同资源摘要。

先完成索引的不可变复制与摘要核验，再分块解析**已保留**的索引，并逐项复制资源。索引路径有独立借用槽，不会被下一项资源路径覆盖。每次操作返回前关闭文件句柄；索引和资源使用两个独立的 SHA context。

现有最终文件必须重新核对长度和实际 SHA256；部分临时文件必须与源文件前缀一致才能续接。损坏目标/前缀不自动删除或覆盖，不把存在当作成功。资源/索引复制失败不会返回 Ready。

v2 对象保留预算为 128 MiB 加 1 MiB 元数据余量、最多 512 个文件，包含未知/孤儿文件。每个完整声明包仍受 64 MiB 上限。原 v1 KML 历史预算保持。目录 Impl 只申请 PSRAM，失败返回 Busy；文件预算不意味着导航/安装成功。

## 内存约束

主清单仍最多 4096 字节，索引仍逐条窗口解析。映射 reader 与输入状态在短期 PSRAM owner；附件校验 owner <=9216 字节，保留 owner <=7168 字节，SD Impl 另计。保留阶段借用已经完成校验的附件 owner 的 I/O、身份映射和两个哈希 context。

准备结果缓存曾在原生编译触及 320 字节限制；已改为只保留返回/重试所需字段，不缓存未使用的 sequence/phase 等头字段，原 <=320 字节断言保持。实际 ObjectHead/持久格式未改。未增加新的可变全局槽，也未放宽大任务栈缓冲规则。运行内存仍需实机复测，不能用这些结构断言替代屏幕 87K/297K 的结果。

## 浏览器录入与恢复 API

签名前冻结附件字节、映射 ID 和能力快照；核对作者、KML、索引及全部提供资源，缺少必需映射在任何上传前拒绝。明确保留的 upload ID 可以复用设备已封存资源，但设备仍实际核对；不能凭网页提供 ID 判断可用。

依次上传 KML、清单、索引、资源及映射，使用 99 轮询，相同操作/上传 ID/父版本在 Busy/未完成重试中保持。最后验证设备返回的真实 v2 签名与对象/版本摘要；原 v1 路径保持。v2 revision 使用 v2 域，object ID 延用 v1 域。新 API 尚未组成完整的多语言附件维护/恢复界面和持久任务投影。
