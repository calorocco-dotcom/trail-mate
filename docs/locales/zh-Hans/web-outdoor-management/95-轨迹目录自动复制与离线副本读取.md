# 轨迹目录自动复制与离线副本读取

2026-10-14，接94。本批把增量清单接入真实轨迹目录运行循环，新增持久有界拉取、KML与资源包复制、原请求重试、文件中断恢复及源节点离线后的新浏览器读取。只改电脑目录端／测试与部署配置，不改设备固件或USB命令，无SDK编译、刷入或设备RAM增加。

## 自动复制流程

独立 `trailmate.track.directory` 签名公告与 `trailmate.track.v1` 扩展能力验证绑定交付目标、公钥与epoch。可配置最多三个发现hash作为提示，仍必须验签，不复用Geocaching地址。服务接收Reticulum签名路径响应，解决后启动节点错过六小时公告的问题。

`TrackReplicaScheduler` 共用服务的Reticulum身份和已验证接收队列，由服务主循环独占SQLite操作。最多32个公告排队／32个目录、一个活动副本请求；清单每页16项，文件块1024字节，每轮256KiB网络预算后让出，完成后300秒轮询，失败按60／300／1800／21600秒退避。不是全网立即一致或吞吐承诺。

冻结清单高水位后，逐个取得精确作者manifest，核对对象／版本／父／状态／文件及格式；缺父可在64层预算内补链。KML和索引按hash与长度分块写入，索引完整匹配原签名后复制必需资源和源目录声明可取得的可选资源。全部必需内容、原作者签名和版本导入完成后，才推进该页检查点。分叉证据沿清单传播，不选择当前赢家。

已有版本也重新核对物理内容：记录存在不能冒充文件仍完整，缺失文件会补取后才推进。坏的既存不可变文件不会无声覆盖，仍须存储故障处理。文件和版本／磁盘配额保持原有界准入。

## 恢复与资源策略

网络请求发出前，持久保存原请求ID与全部请求字节。文件块先持久化，再提交目录进度；崩溃在两者之间可用原范围／ID重试。副本临时上传仅在新字节落盘后延长一小时闲置到期，旧范围重试不续期；普通网页上传期限不变。

epoch改变时重新核对能力并从新清单开始，只清理该目录来源自己的未完成临时上传；保留不可变内容、原签名和版本。错目录、错公钥、错请求、迟到回复、范围／hash／资源绑定错误不能推进检查点。

默认自动文件复制要求Reticulum报告的下一跳速率至少100000bit/s；未知路径先请求签名路径并短期重查，已知慢路径等待。该数值是库提供的接口估计，不是实测吞吐，共享实例可能只报告本地共享接口，NAS应保持预期IP接入。可由运营者显式允许慢链路，Compose默认未开启。此策略不读取或要求切换设备RF协议，网页设备身份仍独立。

部署 `.env` 新增可选 `TRACK_REPLICA_SEEDS`，映射为 `TRAIL_MATE_TRACK_REPLICA_SEEDS`；CLI `--replica-seed` 覆盖环境默认，仍限制三条完整发现hash。与行政区覆盖可共同使用，不改已发布网页或公网服务器。Docker运行源文件已补新模块并通过隔离导入。

## 实际网络验收

两个生产Python轨迹目录进程使用独立身份／存储／Reticulum实例，TCP仅绑定本机。源目录预置隔离作者的v1和v2各三个版本，末版均归档；v2含签名附件索引与真实PNG。没有对网络响应／能力／签名做替身。

- 副本真实下载到2048字节后停止进程，保持持久目录数据，再启动同一副本，交付／发现／epoch保持。
- 重启后完整复制六个签名版本、16502字节KML、原签名索引与必需PNG，检查点到6。
- 停止源目录并实际验证其TCP端口不可连接，再启动新的浏览器客户端。
- 新浏览器只经副本的packet bridge，验证副本能力和原作者签名，读取归档v2、历史3／2／1、精确KML hash／长度、原索引和PNG；完整包ready／allComplete=true，资源verified=true。
- 最终测试退出0，用时20.031秒。证据在 `.codex-build/hostlink-codec/track-replication-network/result.json` 及 `browser/result.json`，明确physicalUsb=false／publicNetwork=false。此前v1单对象相同流程也通过17.897秒。

首次真实测试未通过，定位并修正两个实现缺口：路径响应必须显式交给应用回调；重启保留能力但丢失数据路径时，不能将未知路径仅当慢链路等待。随后验收还发现测试的Windows虚拟环境启动器终止不等于真实进程终止，源端口仍在线；改直接管理实际解释器PID后，离线条件与进程终态才取得有效证据。测试读取SQLite使用显式closing，避免文件句柄干扰临时数据清理。
