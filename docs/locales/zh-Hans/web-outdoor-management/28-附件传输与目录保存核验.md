# 附件传输与目录保存核验

更新：2026-10-13。当前完成浏览器网络 API 与实际 Python 目录/存储的本地联调，尚未接入完整附件 UI、设备包准备/安装和真实公网传输。

## 传输复用

FILE_BEGIN/CHUNK/END 原实现已按 SHA256/长度保存不可变字节，不在上传封存时解释 KML。因此 KML、附件索引和资源都复用操作 4/5/6，单文件最多 8MiB、单块 1024 字节、逐文件串行上传，沿用所有者绑定、持久偏移、重试和封存核验。

历史物理文件后缀 `.kml` 保留以兼容已有存储；它不意味着所有保存字节都是 KML。只有几何读取入口解释经过摘要校验的 KML，资源展示仍须核对实际内容格式。

浏览器在任何上传前验证作者签名、KML 和索引绑定，以及全部提供资源的大小/摘要/ID；先检查预算再复制输入。未提供的必需文件可以复用目录已保存的相同摘要对象，但发布前必须查询完整性，不凭上传计数判断成功。

## 能力协商

普通 `CAPABILITIES`（操作 0、body=[]）仍返回原来的 8 字段、0..8 操作列表，使已有固件的严格解码器继续兼容。

新浏览器显式发出操作 0、body=[2]；新目录仍使用 8 字段形状，操作列表增加 14。旧目录对此返回 422，浏览器保留 v1 基础能力且不启用附件发布。扩展应答的公钥/epoch/预算必须匹配已验证目录；期间连接或 epoch 改变会使检查失败。

没有向旧固件的默认能力公告偷偷加入操作 14，也没有为附件传输要求切换设备 RF 协议。

## 新的公开文件可用性查询

操作 14 的 body 为 `[signed_manifest]`，先验证作者签名与清单格式，再返回：

```text
[1, revision_hash:bin32, kml_available:u8, index_satisfied:u8,
 required_complete:u8,
 [[asset_id,sha256:bin32,size:u32,required:u8,available:u8],...]]
```

index_satisfied 表示索引要求已经满足；无索引的清单该项为 1。索引缺失/损坏时为 0、资源列表为空、required_complete 为 0。有索引时必须核对索引实际字节摘要/长度、KML 绑定、条目数和预算，才能给出其资源列表。

每份文件都重新核对实际长度和 SHA256。required_complete 需要 KML、索引要求及每份必需文件均满足；可选缺失不阻止发布，但 allComplete 在浏览器计算为 false。浏览器核对应答的版本摘要、条目顺序、ID/摘要/长度/必需标记，并重新推导完整性，拒绝矛盾应答。

此查询是目录当前文件可用性声明，不是设备已安装/可渲染/可导航的证明，也不代替当前版本头查询。旧目录保存回执证明当时接受该版本，不能因回执重放就宣称文件现在仍可用。

## 发布核验

目录 v2 发布在任何版本/头写入前要求 KML、索引和全部必需文件通过核验，继续独立从 KML 推导并核对几何范围及点数。可选缺失允许持久接受；公开可用性查询将显示部分文件可用。

浏览器只有在能力、签名、文件及所需资源检查通过后才发送 PUBLISH，并验证目录签名回执。提供错误本地资源时零网络副作用；缺必需文件时不得发送 PUBLISH；上传中丢回复可重新开始同一签名包，复用已封存文件和原发布 request ID，不重签。

## 验证与未完成范围

15 项相关 Node 测试、13 项 Python 回归通过，轨迹网页构建及差异检查通过。新本地桥使用真实 Python BlobStore、DirectoryIndex、TrackApplication、SQLite/磁盘及真实 RNS 作者/目录签名，RNS 传输用 stdin/stdout 模拟，不打开外部接口。

覆盖必需缺失拒绝/无版本写入、可选缺失发布/部分状态、后续可选补全、文件损坏后新查询变为不可用、原回执保持历史含义、数据库重开后资源前缀恢复、无重签、错误本地资源零上传、假完整性应答不发布，以及旧目录/旧能力与 epoch 更换。测试进程明确退出，临时数据在现有缓存内清理。

设备 ManifestFileCheck 的 v2 门禁保持，索引条目窗口、资源准备证明、USB 包传输、KML+附件原子安装还未接入；新的 API 尚未组成多语言附件维护/下载 UI，完整 ZIP 和真实公网/实机/掉电仍待验收。本批没有固件构建/上传，也没有设备 RAM 改动或运行测量。
