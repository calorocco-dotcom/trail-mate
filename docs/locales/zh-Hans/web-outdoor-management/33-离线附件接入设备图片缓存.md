# 离线附件接入设备图片缓存

更新：2026-10-13。延续32的完整包安装与持久查询，补齐已安装包到现有导航/轨迹预览图片缓存的读取通路。本批不是完整图片格式与导航语义交付。

## 已实现

导航图片缓存入口与轨迹预览缓存入口识别设备生成的 `/routes/p-<完整版本SHA256>.kml`。即使尚无网络下载图片，也能将本地包的图片工作交给既有后台缓存任务；轨迹预览的手动图片操作在该分支不要求 Wi-Fi。普通路线的网络下载路径继续使用原有逻辑。

后台 `RoutePackageImageWork` 持有既有路线存储租约，读取本地绑定定位原对象/版本，再由 `StoredPackageInputOwner` 核对原作者签名、实际索引与资源、实际 `/routes` KML 的摘要及几何。CRC只定位记录。索引观察回调只复制候选引用/资源摘要；整个包没有 Ready 之前，禁止使用候选映射。

图片仅按精确引用摘要匹配索引条目，再从版本/资源摘要推导 `.ast` 路径。HTTP地址和相对引用不会成为 SD 路径，不发网络请求、不调用本地内容签名、不更改原包。缺省可选附件没有可用映射；必需缺失或声称已保存的资源损坏不能通过整包校验。

校验完成后立即释放 <=24576B 的源校验工作区，保留 <=6144B 的短期 PSRAM 映射作业。每张图片再以512B片段复制到现有图片缓存候选，核对复制内容与索引的大小/SHA，并读回候选摘要，然后沿既有来源绑定事务提交。来源摘要来自精确解码后的 KML 引用，来源记录本身仍不是作者签名。复制中的换卡、内存/存储失败及摘要不符均拒绝提交。

所有图片复制结束后，释放映射和租约，才调用现有缩略图/查看图解码器；包校验工作区与解码像素工作区不会叠加。没有新增常驻包目录表、后台线程或全局作业槽。缓存列表增加每项32B摘要与有效标志，接口改为按值移动交接，两个UI调用也移动列表，避免启动任务时再复制整份列表。不能用静态 RAM 代替运行峰值测量。

## 完整版本隔离

已安装包的图片目录使用 `/routes/.trailmate/p-<完整版本SHA256>/`，不使用旧路线的32位文件名哈希。导航、轨迹预览、来源绑定与实际复制都采用同一完整版本标识。路径仍固定推导，长资产ID仅接受 `p-` 加64个小写十六进制字符；现有128B路径工作槽足够。

旧路线的目录规则保持。导航自动任务看到相同资产的失败状态会停止自动逐帧重试；轨迹预览可通过原图片按钮重试。状态文字继续走现有本地化展示，新入口没有另加英文操作标签。

来源记录允许到8MiB，与签名附件上限一致；原网络图片批量下载仍请求4MiB上限。旧固件不保证识别大于4MiB的来源记录。

## 剩余固件与网页工作

1. PNG解码和安全分配：当前设备BMP生成器仍只支持JPEG，保存PNG字节不等于可以生成PNG缩略图。已检查现有LovyanGFX PNG依赖，其上下文/扫描行使用普通malloc，不能直接加入内部堆；必须先处理PSRAM分配、尺寸/解码边界，再验证真实PNG。
2. 实机SD、JPEG缩略图和查看图、触摸/菜单、复制失败/掉电恢复及运行峰值。本批原生资源fixture只证明字节保存，不是实际图片解码证据。界面快速“已保存”检查仍只核对来源绑定/长度，不是每次全文件摘要或作者验证；101是独立持久包核验。
3. GPS导航侧完整KML几何/分段、高度与gx时间/缺失样本语义，不能以预览侧实现替代导航侧。
4. 网页多语言完整附件面板、完整包下载/导出、安装任务跨刷新恢复、真实Web Serial与公网目录联调；底层安装/查询API已接入不等于这些页面均完成。
