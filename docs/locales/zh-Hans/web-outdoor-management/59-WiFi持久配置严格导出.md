# Wi-Fi持久配置严格导出

## 修正的问题

原TMS导出通过visit_saved_profiles遍历Wi-Fi运行时缓存。缓存加载用旧get接口读取配置数量、SSID和密码：读取失败与不存在无法区分，无法读取的槽位被跳过，密码可回退为空或旧键，过长字符串被截断。运行时缓存已经存在时，导出甚至不会重新检查持久化存储。网页因此可能得到一份看似完整、实际少了网络或密码的配置。

新增ESP专用read_saved_profiles_into。common和P4/C6 IDF后端共用严格持久读取实现；完整TMS导出改调用该接口，直接使用现有ParseState.wifi_profiles PSRAM暂存。连接缓存、当前连接、扫描、自动重试及旧运行时加载入口保留原行为。新的读取不能被用于宣称运行时加载错误也全部修复。

## 读取与兼容规则

- bool和配置数量只允许Missing使用既有默认，Invalid／Unavailable返回失败；数量不夹取，必须0到10。
- 数量大于0时，声明的每个槽位必须具有非空有效SSID，不允许缺失或重复槽位静默缩短集合。
- SSID和密码按32／64字节容量有界读取，不截断。错误不变成空密码；当前密码仅在Missing时读取旧wifi_pass键。当前空密码保留优先级，两种键均不存在时保留开放网络语义。
- 数量缺失或0时保留旧固件扫描十槽的恢复语义；稀疏槽位与旧密码仍可读取，重复SSID保留第一次的优先级。不会迁移、删除或补写任何键。
- 旧主SSID／密码保持原有回退及追加语义，同SSID主镜像不覆盖槽位密码；超出十个唯一网络时返回失败，不静默丢失第十一个。
- 读取失败清空候选缓冲及数量／启用输出。参数容量不足时仅清空调用方声明的范围，不越界。失败后完整配置writer返回失败，后续BLE owner不运行。

这不是跨NVS键的原子快照事务。并发变更、一致性恢复、真实存储错误和实际任务峰值仍须验收。
