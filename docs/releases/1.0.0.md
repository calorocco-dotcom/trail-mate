# Trail Mate 1.0.0 正式版交付

状态：准备中。此文件记录用户明确要求的发布范围，不代表正式版已经发布。

完成设备 Web 配置管理、设备身份的 Geocaching 维护、去中心化 KML 轨迹维护与分享，并通过验收后，发布首个正式固件版本 `1.0.0`。版本、网站、README、Changelog 和 Wiki 应描述同一套已验收功能。

## 去中心化和隐私

用户控制设备身份和本地记录，不必把全部个人轨迹交给同一账户平台。浏览器通过 USB 使用设备作者身份，电脑网络承载 Reticulum 请求；不要求切换设备聊天／RF 协议。目录与网关可由不同运营者提供，接收者可独立验证作者签名。

这减少单一平台统一收集和关联所有用户活动的机会，但不能保证公开信息不可被保存或分析。公开路线、坐标、时间、公钥和元数据对目录及下载者可见；同一作者的公开活动也可能被关联。网关及外部地图服务可观察其连接或地图请求。归档更新发布状态，不能撤回他人已复制的历史数据。

README 和 Wiki 不得声称“任何平台都无法掌握轨迹或行为”。应说明哪些数据留在本地、用户选择共享什么，以及接收方能看到什么。

## 固件卡片建议的评估边界

参考 Contacts 的单卡片／按需水合方式评估 Tracker 与 Geocaching。Tracker 当前重建最多32个记录或64个路线按钮，Geocaching 已按窗口读取一小页，两者收益不同。若采用，应只复用单张卡片、只水合当前项，图片和详情按需打开，避免逐项 KML 解析和常驻预读。

这项建议目前是评估，不自动成为原三功能的发布门槛，也不追加新卡片框架。
